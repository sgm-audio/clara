# ADR-010: Dual-Path Conditioning Architecture

**Status:** Accepted  
**Date:** 2026-06-07  
**Replaces:** ADR-008 §2 (conditioning path)

## Context

ADR-008 described conditioning as an external scalar gain modulation applied post-inference, with `COND_DIM=8` and explicit statement that it "does not change the ONNX I/O contract." The implementation evolved to include BOTH an ONNX-integrated conditioning path AND the external gain modulation.

## Decision

**Conditioning operates through two parallel paths:**

### Path 1: ONNX-Integrated `cond` Input (10th model input)
- The ONNX model accepts a `cond` tensor of shape `{1, 8}` as its 10th input
- This is applied internally by the model's FiLM (Feature-wise Linear Modulation) conditioning layers
- The engine provides this via `inputNames_[9] = "cond"` and `inputTensors_[9]`
- `kNumInputs = 10` (was 9 in ADR-001, updated to reflect the cond input)

### Path 2: External Scalar Gain Modulation
- After inference, if `condWeightsLoaded_` is true, the engine applies:
  ```
  output[i] *= (1.0f + Σ(cond[d] * combinedWeights_[d]))
  ```
  where `combinedWeights_[d] = deltaWeights[d] + bWeights[d]`
- This is a per-sample scalar gain adjustment based on the conditioning projection weights

### Why Both Paths Exist
1. **Path 1 (ONNX)** allows the model to learn complex nonlinear conditioning (FiLM layers can modulate arbitrary internal activations)
2. **Path 2 (External)** provides a deterministic, inspectable linear modulation that doesn't depend on the model's internal FiLM weights

When both paths are active, the conditioning is effectively applied twice — once inside the ONNX model (FiLM) and once externally (scalar gain). A fully trained model with non-zero conditioning projection weights (`deltaWeights`, `bWeights`) and trained FiLM layers will converge to an equilibrium where the double-application produces the intended effect.

### TOCTOU Safety
The conditioning frame (`condFrame`) is snapshotted once per sub-block (line 241) and reused for both paths, preventing a time-of-check-to-time-of-use race where `setConditioning()` changes the frame between ONNX inference and external modulation.

## Consequences

- ADR-001 must be read as describing 10 inputs, not 9
- `CondConditioningFrame` holds `kCondDim=8` floats per frame
- `setConditioning()` writes to a double-buffered frame with atomic pointer swap (safe from any thread)
- Both conditioning paths are dormant until model training produces non-zero projection weights
- The ARA content bridge (CLARA-09) is needed to populate the cond vector with actual musical context values
