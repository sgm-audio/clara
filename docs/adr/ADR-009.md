# ADR-009: Sub-Block Processing at 64 Samples

**Status:** HISTORICAL — Describes ONNX Runtime sub-block processing with `Ort::Session::Run()`. Superseded by PerTrackProcessor spectral-domain processing (ADR-011) which uses frame-based STFT/ISTFT processing rather than per-sample sub-blocks. The `MAX_CHUNK_SIZE=64` constant persists in `MambaConfig.h` for the legacy R=4 engine.
**Date:** 2026-06-07 | **Superseded:** 2026-07-02
**Replaces:** ADR-001 §4.1 (block-size handling)

## Context

The ONNX model is exported with a fixed sequence length. The initial implementation used `seq_len=256`, but to reduce memory pressure and improve real-time safety, the engine was re-exported with `seq_len=64` and an internal sub-block chunking loop in `processBlock()`.

## Decision

**The engine processes audio in fixed 64-sample sub-blocks**, regardless of the host's buffer size.

- `kSubBlockSize = 64` (static constexpr, `MambaInferenceEngine.hpp:65`)
- The ONNX model accepts `{1, 64, 1}` shaped audio input tensors
- `processBlock()` chunks incoming audio into 64-sample slices in a while-loop (line 213)
- Partial final chunks are zero-padded to 64 samples for the ONNX Run, then only the valid portion is copied to output

### Rationale

1. **Memory:** 64-sample sub-blocks require 1/4 the ONNX tensor memory vs 256-sample blocks
2. **Latency:** The model's convolutional prefix (4 samples) already determines latency; sub-block size doesn't add further delay
3. **RT Safety:** Smaller per-Run allocations mean less time spent inside `Ort::Session::Run()`, reducing the risk of audio dropouts
4. **State Continuity:** SSM and conv state is carried across sub-blocks via explicit `memcpy` from stacked output tensors back to per-layer input tensors

### Consequences

- `maxBlockSize` in Config determines the internal buffer allocation, not the ONNX sequence length
- Any model export must use `seq_len=64` (enforced by `export_mamba_onnx.py`)
- Thread-local `Ort::Value` vectors are re-created each sub-block but pre-reserved to avoid heap allocations
- Zero-padding the final sub-block should not introduce artifacts since the SSM state is properly carried forward; the padded zeros only affect ONNX Run's output for those samples, which are then discarded
