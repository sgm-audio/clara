# Model files — what is in here, and why it is not what the README used to claim

## Current contents

| File | Size | What it is |
|---|---|---|
| `model.bin` | 6,649,600 B | Weight file in the V2 flat-binary format. **Untrained** — Xavier-random weights generated by `python/tools/export_mamba_weights.py --seed 42`. Semantically the same thing the old `model.bin`/`model_ref.bin` test fixtures were; the bytes are new. |
| `input_ref.bin` | 2,052 B | 512 float32 samples (440 Hz sine, 0.5 amplitude) + `uint32` length prefix. Python reference input for `test_mamba3`. |
| `output_ref.bin` | 2,052 B | 512 float32 samples produced by `python/reference_forward.py` from `model.bin`, same conditioning the C++ test uses. |
| `ref_meta.txt` | — | Provenance for the two fixtures: model sha256, sample count, conditioning values. |

`model.bin` sha256: `bc10f7636a0583b69032111a910678b7bc1b9dcef4fada4b6ea123ffa538639e`

The plugin loads `model.bin` at `init()` and produces audio with it. Because the
weights are random, that audio is **not a trained effect** — it is a working
signal path through a randomly initialized network.

## What was here before, and what was lost

These files were tracked by **Git LFS** until 2026-10-04. The account's LFS
budget was exceeded, so the LFS API returns

```
403  This repository exceeded its LFS budget.
```

for every object — authenticated or not. Every clone therefore received 132-byte
pointer files instead of weights, which meant:

* the plugin failed to load (`mamba_init()` returns false when weights are
  unreadable), so it did not pass audio in a DAW;
* `test_mamba3` aborted with `std::bad_alloc` (the pointer file's text was parsed
  as a weight header, and the "sample count" it read implied a ~7.7 GB buffer).

The blobs referenced by the deleted pointers, for the record — they can be
restored if the account's LFS budget is raised:

| Path | LFS oid (sha256) | Size |
|---|---|---|
| `model.bin` | `5bbde5682e2fb62bbeb6a57af0f2f2e9820c88497dfbca73ec7ed9a9b5dbb7f0` | 6,649,600 |
| `model_trained.bin` | `5bbde5682e2fb62bbeb6a57af0f2f2e9820c88497dfbca73ec7ed9a9b5dbb7f0` | 6,649,600 |
| `model_ref.bin` | `df69b700c7b8d75e97f668860c1d63b32ad76acaadc5dd360d9b16caa2257e1b` | 6,649,600 |

Note that `model.bin` and `model_trained.bin` shared one oid: the file described
as the "briefly trained identity autoencoder" was byte-identical to the test
fixture. There is no evidence in the repository of trained weights that differ
from the generated fixture.

`.gitattributes` no longer applies the LFS filter to `models/*.bin`. The model is
6.6 MB, so it belongs in Git directly.

## Regenerating or replacing

```bash
# Regenerate the random fixture + Python reference fixtures (needs numpy + torch)
python3 python/tools/export_mamba_weights.py --output models/model.bin --seed 42
python3 python/tools/dump_engine_reference.py --model models/model.bin --output-dir models

# Install a real trained model instead (R=4, V2 format, 6,649,600 bytes)
python3 python/training/train_local_radeon.py \
    --export checkpoints_clara/best.pt --output models/model.bin
python3 python/tools/validate_export.py models/model.bin
python3 python/tools/dump_engine_reference.py --model models/model.bin --output-dir models
./build/tests/test_mamba3 models/model.bin
```

If the model changes, **regenerate the reference fixtures** — they encode the
output of that specific model, and `test_mamba3` compares the engine against
them. `ref_meta.txt` records which model the fixtures belong to.
