# CLARA — Mamba Audio Suite (CLAP + ARA2 + VST3)

**Current state (2026-10-04):** C++17 audio plugin running a Mamba-3 SSM (R=4
time-domain, multi-head MIMO, RoPE, trapezoidal) through a custom C++ engine — no
ONNX Runtime. Linux builds and tests pass. **Two blocking facts to know before
promising anything:** (1) the engine costs ~0.26 ms/sample, i.e. ~1,250% of one
core per 48 kHz mono stream, so it is not real-time; (2) `models/model.bin` is an
untrained random fixture, not a trained effect.

**Read first:** `docs/BLUEPRINT_COMPARISON.md` — the verification pass with all
measurements. `docs/TODO.md` — open work (stability, compute budget, H3).
`models/README.md` — what the weight files are and what was lost.

**Build:** `cmake -B build -DBUILD_TESTING=ON -DCMAKE_POLICY_VERSION_MINIMUM=3.5 && cmake --build build --parallel && ctest --test-dir build`
— needs `libx11-dev`. With tests: `test_mamba3` (21 checks), `test_perf_budget`,
`test_clap_plugin`, `test_ara_controller`, `clap_validator` (SKIPs without the binary).

C++17 audio plugin producing `MambaSuiteClap.clap`, `MambaSuite.vst3` (clap-wrapper)
and `MambaSuiteARA.so`.

## Engine architecture (current)

- Mamba-3 R=4 time-domain: RoPE rotation, trapezoidal SSM, multi-head MIMO rank 4,
  FiLM conditioning. d_model=128, d_state=32, d_inner=256, 6 layers, ~1.66M params.
- `src/core/SsmInferenceCore` drives the stack; `src/core/SsmBlock` holds the 8-step
  per-sample pipeline plus the batched entry points.
- **Execution model:** the host block is split into `PROCESS_CHUNK_SIZE` (128)
  chunks, processed layer-major. Per chunk: conditioning projections are evaluated
  once (`prepare_conditioning`), FiLM is applied in place, `in_proj`/`out_proj` run
  as register-blocked GEMMs (`gemm_blocked<BJ,BI,K>`), and the recurrence runs
  per-sample (`sample_core_batch` → `sample_core`). This is a *scheduling*
  decision: it does not change the model, only float32 summation order.
  Tile size is a compile-time knob (`CLARA_GEMM_BJ`/`CLARA_GEMM_BI`, default 4x16).
- **Invariants to preserve:** zero heap allocations on the audio thread (all
  scratch is engine-owned, allocated once in `init()`); the RoPE angle state is
  advanced *before* the rotation (matching `python/reference_forward.py`);
  `MAX_CHUNK_SIZE` (64) is model semantics and must match training — do not
  confuse it with `PROCESS_CHUNK_SIZE` (128), which is performance only.
- Weights: V2 flat binary, 64-byte header + 13 arrays/layer, validated strictly
  (magic, version, every dimension, exact payload size) before `mmap` pointers are
  handed out. A file that is not exactly the declared size is rejected.

**Target architecture (not started):** PerTrackProcessor R=8 spectral-domain
(~4.26M params, complex poles, STFT frontend, CREPE conditioning, cross-track
attention). See `docs/MAMBA3_MIGRATION_PLAN.md` and H3 in `docs/TODO.md`. Note the
tension: a 4.26M-param spectral model is *further* from real time than the current
1.66M time-domain one — resolve the compute budget question first.

## Measured performance (Xeon 2.6 GHz, 2 vCPU)

| Build | Per sample | 1 stream @48k mono | RTF |
|---|---|---|---|
| Original code (pre-2026-10-04) | 0.379 ms | 1,820% of one core | 0.055x |
| Current, repo Release flags | 0.262 ms | 1,256% | 0.080x |
| Current, `-march=native` | 0.188 ms | 903% | 0.111x |

Per sample per layer: `in_proj` 0.0246 ms (57%), recurrence 0.0148 ms (34%),
`out_proj` 0.0037 ms (9%). The GEMM is at this CPU's FP issue limit; further gains
must come from model size, not kernel tuning. `test_perf_budget` fails the build if
the cost ratio (engine vs a same-machine calibration loop) exceeds 3.0.

## Numerical behaviour (known issue)

The float32 recurrence amplifies rounding: vs a float64 oracle of the same
pipeline, output diverges 2.0% of peak within 12 ms and 7.3% within 93 ms; a
1-ULP input change grows to 0.1% of peak over 85 ms. Peak state magnitude sits at
1.000, meaning the 4096-sample clamp (`SSMState::normalize_if_needed`) is active.
Output stays finite (no NaN/Inf), which is why the old stability test passed.
`test_numeric_sensitivity` reports the drift; see `docs/TODO.md` for the fix path.

## Model files

Committed to Git, no Git LFS (the LFS budget was exceeded on 2026-10-04, which had
made every clone ship 132-byte pointer files — the plugin would not load and
`test_mamba3` aborted with `std::bad_alloc`). `models/model.bin` is a 6.6 MB
untrained fixture; `input_ref.bin`/`output_ref.bin` are Python reference fixtures
generated by `python/tools/dump_engine_reference.py` (which runs the same model
through `python/reference_forward.py`). Regenerate the fixtures whenever the model
changes. The test suite does not need torch; the generator does.

## Python reference

`python/reference_forward.py` is the engine-equivalent R=4 implementation and the
oracle for `test_python_reference`. It was unimportable (SyntaxError) and diverged
from the engine in five places until 2026-10-04 — treat the module docstring as the
record of the alignment. `train_clara.py` (R=8 PerTrackProcessor) is a *different*
model and must never be compared against the C++ engine; the old
`dump_reference_output.py` did exactly that, which made the "bit-exact" test
impossible. That script is now a shim.

## Key design constraints

- All SSM state and batch scratch are engine-owned; no heap on the audio thread
- `ARA::PlugIn::PlugInEntry::getPlugInEntry<F, D>()` creates static singletons —
  no custom constructor args
- ARA 2.0 has no `renderSamples()`; audio goes through the companion CLAP plugin
- Model path resolution via `mambaResolveModulePath()` (`Platform.hpp`), models in
  `models/` adjacent to the plugin binary
- CLAP text/audio encoders are a future feature; conditioning uses a 128-dim `cond`
  vector

## C++ conventions

- C++17, `-ffast-math -O3 -DNDEBUG -fno-rtti` in Release, `-Wall -Wextra -Werror=return-type`
- Keep GCC's `-Waggressive-loop-optimizations` quiet: bound GEMM dimensions and
  avoid `ptr[i * K]` remainder loops (use pointer increments)
- Symbols hidden; `$ORIGIN` RPATH; `init()` returns bool, never throws
- Pre-commit hooks: clang-format (C++, 120 cols), black, ruff, file hygiene

## Verification

```bash
cmake -B build -DBUILD_TESTING=ON -DCMAKE_POLICY_VERSION_MINIMUM=3.5
cmake --build build --parallel
ctest --test-dir build --output-on-failure
./build/tests/test_mamba3 models/model.bin       # verbose per-check output
./build/tests/test_perf_budget models/model.bin  # compute budget + RTF report
```

CI (`.github/workflows/ci.yml`) builds Release + VST3 on three platforms, verifies
symbols, RPATH and that `model.bin` is not an LFS pointer / truncated file, runs
clap-validator (pinned asset), and runs CTest.

## Known gaps

| Gap | Severity | Status |
|---|---|---|
| Compute budget: ~12x too slow for stereo real time | 🔴 Blocking | Measured; needs a smaller model |
| Numerical drift under float32 | 🟡 High | Quantified by `test_numeric_sensitivity` |
| Per-sample cost of the recurrence | 🟡 Med | State layout `[h][s][d]` would let the inner loop vectorize (~34% of cost) |
| No trained model shipped | 🔴 Blocking for product | Weights lost with the LFS budget |
| No DAW load test | 🟡 High | Never performed |
| Per-effect variants, presets, installers | 🟡 Med | Not started |
| H3: R=8 PerTrackProcessor engine | 🟡 Med | Not started (see compute-budget note above) |
| macOS/Windows verification | 🟡 Med | Presets exist, untested |

## Session logging — mandatory at session close

`SESSION_LOG.md` is an append-only log; write a new entry at the end of every
session, and update this file if the state changes. The user should be able to
start a session by reading only `SESSION_LOG.md`.
